## 벡터 DB 후보 조사

참고: https://datafisher.tistory.com/entry/Vector-DB는-무엇을-해결하는가-가장-비슷한것을-빠르게-찾는-검색-엔진

| | Chroma | FAISS |
|---|---|---|
| 성격 | 임베디드 벡터 DB (DB에 가까움) | 벡터 검색 라이브러리 |
| 설치/설정 | 매우 간단, `pip install chromadb`로 바로 사용 | 라이브러리 직접 다뤄야 해서 상대적으로 손이 감 |
| 메타데이터 필터링 | 기본 지원 (문서 출처, 타임스탬프 등으로 필터링 가능) | 벡터 검색만 지원, 필터링은 직접 구현해야 함 |
| 확장성 | 소규모 프로토타입에 적합 | 수십억 개 벡터까지 확장 가능 |
| 우리 프로젝트 적합도 | 높음 — 문서 30~50개 규모, 빠른 프로토타이핑 | 과함 — 이 정도 규모엔 불필요한 복잡도 |

**추천**: Chroma. 우리 프로젝트 규모(문서 수십 개)에는 FAISS의 대규모 확장성이 필요 없고, Chroma가 메타데이터 필터링을 기본 지원해서 나중에 "포이즈닝된 문서만 필터링" 같은 실험을 붙이기도 더 쉬움.

## 결론

⇒ 임베딩 모델은 `Qwen3-Embedding-0.6B`, 벡터 DB는 `Chroma` 사용. (LLM 백엔드는 추후 직접 조사해서 확정)
